# САМО v6 audit and v7 candidate — 2026-11-02

## Scope and production state

Read-only inspection of production was performed before candidate work. Production remains the immutable `samo-ecology-v6-morphology` protocol on `--arm neutral`; the active unit was healthy, had no technical restarts, and the database passed SQLite `quick_check`. At inspection it had 41,951 steps, episode 32, three active organisms, 33 retained episode summaries, 32 recolonizations, 11,019 morphology births, 9,944 genotype changes, and 2,601 phenotype effects. The source and protocol hashes matched the repository release. The public origin served v6 snapshots with no-cache headers and the live React page displayed the current v6 protocol and latest form. The `v4` prefix in organism IDs is the frozen computational-core namespace used by v6, not evidence that v4 morphology or protocol was active.

Production resource values were read from its cgroup: CPU quota 40% of one logical CPU, memory maximum 512,000,000 bytes, swap maximum 0. No systemd, network, TunnelDeck, HTTPS, or firewall settings were changed.

## Confirmed v6 findings

- Production runs the neutral arm. The descriptor archive does not select morphology proposals in this arm, so archive presence is not evidence that archive-directed search is active.
- Morphology changes are attached to accepted computational births/recolonizations. v6 has no separate within-lineage morphology event. That is a protocol choice, not a recorder bug.
- Neutral v6 samples among four morphology proposals without using morphology fitness. It does not protect the final living representative of a morphology niche.
- `sphere_returns` counts a transition to a phenotype whose nodes are all primitive spheres. It does not measure spatial clumping. Spatial collapse needs a separate geometric measure.
- The retained checkpoint had 2,831 `retention_steps` keys despite a 64-cell archive. This history map can grow independently of the archive bound. v7 uses a 512-key cap and a hash-chain commitment for evicted records.
- Event payload retention is bounded and old payloads are pruned after hash-chain commitment. The surviving episode summaries report extinction, but the pruned events mean the precise causes of every historical sphere return or lineage change cannot be reconstructed. No cause is inferred where the evidence was pruned.
- The observed 146 sphere returns are therefore genuine all-sphere transitions according to the existing metric, but they cannot be reclassified retrospectively as spatial collapse from retained v6 data.
- The v6 founder generator starts from a small grammar and applies a small number of mutations. This is a documented founder bias, not a hidden revival of an archived genotype.

## v7 candidate design

The candidate keeps `samo.ecology_v4` compute transitions/evaluation frozen in all arms except the explicitly registered `v7_niche_survival` arm, which vetoes a computational replacement that would remove the last active representative of a morphology niche. Other arms change only morphology proposal generation/choice or apply a separately recorded within-lineage morphology mutation. Archive records contain descriptors only; no archived genotype can become a parent. Founders after extinction receive newly generated seeded rule graphs.

The v3 morphology language is an inert bounded rule graph: no file, network, process, or system calls. It has explicit instruction, recursion, node, coordinate, scale and fuel caps. Geometry, connected components, all-sphere returns, compactness and three orthographic silhouettes are separate measurements; no single “progress” score is produced. Morphology changes do not count as compute births or predictive improvements. The frozen v4 core intentionally starts with an empty population; its first transition records founders, and v7 assigns their morphologies in those same founding events. Step-zero emptiness is not a missing-trait defect.

Protocol v5 is preregistered at [ecology-v7-morphology.json](../protocols/ecology-v7-morphology.json). It defines seven arms (v6 control plus six v7 modes), eight paired seeds and short/medium/long tiers. Each arm has the same **maximum** CPU, combined VM-fuel and step ceilings. Actual CPU time, combined/compute/morphology fuel, steps, database size, RSS, and systemd cgroup limits are recorded. Resource caps are matched; realized consumption is not identical and is reported below. That distinction matters because some runs stop on fuel before consuming the CPU ceiling.

The v1 pilot was interrupted while investigating a suspected step-zero morphology gap; source review confirmed the core's empty initial state is intentional, so that concern is resolved. The v2 pilot was stopped after discovering that a continuous resume/export runtime was missing. A v3 pilot was interrupted while the static export schema was being aligned with React. A v4 pilot was stopped when privacy text on the candidate site incorrectly named Cloudflare as the host. Those archives remain separate, are labelled interrupted, and are excluded from the v5 comparisons.

## Durable runtime and isolation checks

`python -m morphology.runtime_v7 run` now resumes only a checkpoint whose source/protocol hashes and invocation configuration match. Each transition is transactionally checkpointed; signals stop after the active transition has been committed and exported. Public output is a size-bounded static JSON snapshot written with atomic replacement and directory fsync. There is no organism control API. `verify` checks checkpoint and SQLite integrity without exposing writable state.

The Linux acceptance VM uses a 1,000,000,000-byte ext4 loop filesystem mounted `noexec,nosuid,nodev`. The service is run through systemd with `CPUQuota=40%`, `MemoryMax=512000000`, `MemorySwapMax=0`, `TasksMax=32`, `PrivateNetwork=yes`, only `AF_UNIX`, a read-only project tree and one writable state directory. The isolation acceptance probe observed `cpu.max=40000 100000`, `memory.max=512000000`, `memory.swap.max=0`, `pids.max=32`, only loopback, denied outbound socket access, denied writes outside the state directory, and the ext4 `noexec` mount.

Candidate unit coverage includes deterministic founder generation, bounded hostile recursive genomes, separate morphology-only events, fresh recolonization, descriptor-only archive, the explicit selection veto, v6 compute-core replay, bounded retention/hash commitment, step-zero/founding export, and kill/restart checkpoint recovery. The final 14 tests passed inside the isolated Linux VM. The isolation probe observed `cpu.max=40000 100000`, `memory.max=512000000`, `memory.swap.max=0`, `pids.max=32`, loopback only, blocked outbound connections, denied writes outside the state path, and an ext4 `noexec` project mount. ## Diagnostic comparisons and corrected replay audit

The first complete diagnostic matrix contained 28 runs: two paired seeds × two tiers × seven arms. Every row and event is retained under ignored `output/research-v7/matrix-v5/`. The compressed SQLite/JSON archive is 29,176,453 bytes; its SHA-256 is `782536fc4c9c46e408fe11e2d90650ed33e09b97fb20107f3ef9e3ddea2925e8`. The protocol hash was `603a05653abe7b0ab2626256a4b5b315b5cb12c11a2c9e5ef8e0513e5d8c7a74` and the run-time source hash was `dc44e827525ff034c05174520b517ca24a38ac3dd28a338198fb211f14800251`.

The original matrix runner returned a failure even though all 28 replicates were saved. The failure was in the *audit comparator*: it hashed the full v6 event envelope but only the nested computational transition in v7. The separately implemented archive verifier checked every saved event hash, then compared the same `computational` projection for both protocols. It found zero unexpected compute divergences in all ordinary v7 arms. In the explicitly registered `v7_niche_survival` arm, compute state diverged after the first recorded niche-survival veto, as expected. The raw results were not changed; a regression test now covers both event formats. Corrected replay details are saved in `output/research-v7/matrix-v5/corrected-replay-audit.json`.

At medium tier, the two-seed mean number of active silhouettes was 1.5 for v7 neutral, 3.5 for novelty, 2 for live-niche search, 2 for niche-survival, 3 for descriptor-archive diversity, and 1.5 for dual-rate. These are descriptive numbers from n=2 only. v6 did not emit the new silhouette metric, so a direct v6/v7 silhouette comparison is not available. Medium-tier v7 novelty/descriptor archive used more morphology fuel than compute fuel in some runs; some replicates reached the VM-fuel limit before the nominal 400-step ceiling. The equal *ceilings* therefore do not establish equal *realized* costs or a reliable treatment advantage. The max observed inherited-feature age varied substantially by arm, including lower values in the novelty run; no durable superiority is demonstrated.

No independent compute-capability evaluation was run for v7, and the morphology-only arms retain the frozen v4 computational core. This experiment provides no evidence of a new prediction ability or of a compute-performance improvement. The niche-survival mode intentionally changes compute selection and substantially reduces births in the tiny pilot; it must remain a separately named scientific intervention.

Following the audit-comparator correction, a fresh preregistered matrix has been started in the isolated VM using all eight registered seeds and all three tiers. It is **in progress**, not a result. Its archive and per-run measurements are separate from v5. No inferential or production claim will be made until it completes and its event hashes, resource records and replay checks pass.
