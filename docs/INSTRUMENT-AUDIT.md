Причина расхождения e5b333… / активной population: старый `Specimen` на странице `/organism` получал `Run.active_hash` из замороженного `snapshot.json` пилота, а отдельный блок над ним получал `ecosystem.json`. Ошибка загрузки живых данных не включает пилот как запасной геном.

## Прибор

`web/src/instrument.tsx`: одно кольцо на модуль, search, каждую из четырёх dialect-программ, router и память. Равные внутри кольца дуги соответствуют одной инструкции/слову. Угловой размер — 0.86 × 2π/N, радиус 253 − 11k, ширина 5 (8 при фокусе). Пустые компоненты не рисуют фиктивные элементы. Число дуг равно сумме длин всех этих массивов. Семантический эффект не выводится из цвета или длины.

Каждая дуга имеет title, role=button, tabindex, реальные opcode/argument и координату компонента; доступны hover, click, клавиатура и текстовый эквивалент. Центр содержит ID, проверенный hash, состояние и размер генома; рядом — время наблюдения, родители, наблюдаемые потомки и реальные изменения. По умолчанию выбирается самая ранняя родившаяся активная форма, затем ID; это порядок просмотра, не лидер. Доступны все активные формы, до 80 retained candidate genomes и ограниченный клиентский кэш. Отклонённый кандидат не называется живой особью. Для далёких предков/потомков, отсутствующих в retention window, полнота не заявляется.

Браузер пересчитывает SHA-256 канонического JSON генома, проверяет структуру и запрещает один ID с несовместимыми hashes. Неизвестные схема/протокол отклоняются. Новые снимки получают startTransition; именованный View Transition показывает смену реального кадра, изменившиеся инструкции выделяются однократно. Декоративного вращения нет, reduced-motion отключает анимацию. Смена просматриваемой формы сама по себе не объявляется наследуемым архитектурным переходом.

## Fitness v2

`tools/audit_fitness.py` заново воспроизвёл первые 1014 попыток из приватного seed исходного производственного checkpoint, не используя готовые агрегаты как вход. Получено: 984 кандидата, 984 приняты, 979 нулевых exact-match, 5 ненулевых, 30 бесплодных попыток, две ненулевые delta. Это совпадает с исходным снимком.

В реализации delta сравнивает ребёнка с одним случайным incumbent, оценённым на той же свежей задаче. Metropolis использует exp(min(0,delta/0.08)); при равенстве вероятность принятия равна 1. Следовательно, почти полное принятие объясняется разреженным exact-match и правилом нейтрального отбора. Это преимущественно дрейф в проверенном срезе, а не доказанное обучение. Четыре разных genotype hash дали один behavior hash на общем отдельном диагностическом task suite; это ограниченный тест, не доказательство эквивалентности любых программ.

Зафиксировано 85 реально использованных search hashes. Сам факт смены hash не доказывает полезности. Наследование поиска и семантическое исполнение проверялись тестами ядра; геномы остаются ограниченным байткодом без сети/файлов/LLM. Изменения search/dialect/memory исполняются, но полезный эффект и специализация не доказаны.

Побитовая точность и нормированная MAE вычислены по тем же raw trial predictions: диапазоны 0…1. Они могут давать градуированный сигнал, но содержат смещения: равный вес битов не всегда соответствует структуре процесса, линейная MAE не учитывает близость по модулю 65536, а ловушки требуют отдельного штрафа и coverage. Ни одна не объявляется улучшением. Селектор v3 и сравнение новых методов здесь не вводились: сначала нужна отдельная предрегистрация контролей, matched fuel и независимых confirmation streams. Действующий v2 не изменялся.

## Регистратор и доставка

Добавлен независимый observer (`tools/enrich_snapshot.py`) вместо прежнего export invocation в systemd drop-in. Он использует проверенный read-only memory snapshot, не исполняет геномы и не меняет checkpoint. Сохраняет bounded aggregate bins, общий счётчик наблюдавшихся результатов, 64 архитектурных milestones со сравнением размеров родителя/кандидата и явными утратами, 256 последних агрегатных блоков. Более старые блоки сворачиваются в счётчики и hash commitment. Пропуски до начала наблюдения явно записаны; старые raw trials не восстанавливаются выдуманными значениями. Протокол научного отбора и source hash ядра остаются прежними.

Важное ограничение: необратимо сокращённые raw данные не содержатся в агрегатах. Их реконструкция требует приватного seed и точной архивированной версии кода; общая multi-year доказательность всех механизмов не подтверждена одним replay. Важные изменения представлены ограниченной выборкой milestones, а не полным бесконечным архивом.

Публичный JSON содержит step и snapshot_id (checkpoint hash), время последнего вычисления, время формирования экспорта и время передачи publisher. Последнее не гарантирует момент глобального распространения KV. React опрашивает источник раз в минуту и при возвращении на вкладку; старые step не заменяют новый кадр. Доставка примерно раз в три минуты, KV может добавить задержку. При достоверном inactive состоянии службы оно показывается с временем проверки; иначе причина устаревания явно неизвестна. Нового public write/control API нет.

Все новые writable observer-файлы находятся внутри существующего loop volume, exporter работает в прежнем auxiliary slice. Observer прошёл Ubuntu VM smoke/bounds checks. Научное ядро не обновлялось и эксперимент не перезапускался. TunnelDeck и его сеть не изменялись.
