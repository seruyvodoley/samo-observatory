# SAMO VM ABI 1

Машинная программа — JSON-массив `[opcode, arg]`. `opcode` — индекс в таблице; `arg` — целое от -65535 до 65535. После арифметики сохраняются младшие 16 бит. Максимум 96 инструкций, стек 128 слов, память 64 слова, emission 64 слова, история 256 значений. Числа/коды bool не принимаются. Нет файлов, сети, импорта, host execution или внешних часов.

| Код | Имя | Семантика |
|---|---|---|
|0|CONST|Поместить arg mod 65536 в стек|
|1|HIST|Поместить history[-1-index], index по модулю длины. arg≥0 — постоянный index, arg<0 — снять index со стека. Пустая история даёт 0|
|2|MEM|Аналогично HIST, но чтение memory[index]. Пустая память даёт 0|
|3|ADD|Снять b, a, положить a+b mod 65536|
|4|SUB|a-b mod 65536|
|5|MUL|a*b mod 65536|
|6|XOR|a XOR b|
|7|MOD|a mod b; b=0 даёт 0|
|8|DUP|a → a,a|
|9|DROP|Удалить верхнее слово|
|10|SWAP|a,b → b,a|
|11|JMP|pc := arg mod (code_length+1)|
|12|JZ|Снять слово; если ноль — JMP arg|
|13|RAND|Слово от поискового PRNG; в предсказании capability отсутствует и возникает trap|
|14|EMIT|Снять слово в отдельный bounded output|
|15|CALL|Исполнить dialect[arg mod 4], передав текущий стек, историю и локальную память. Результат заменяет стек одним словом. В семантическом коде CALL запрещён; общий Meter не сбрасывается|
|16|LEN|Поместить длину наблюдённого префикса|
|17|STORE|При arg≥0 снять значение и записать memory[arg mod length]. При arg<0 сначала снять index, затем значение. При пустой памяти снять одно верхнее слово независимо от arg, без записи|
|18|HALT|Завершить исполнение|

После выхода за границу кода исполнение заканчивается. Результат — вершина стека или 0, emission и новая локальная память. Underflow, fuel, deadline и превышение размеров — ловушки с явно сохранённым статусом. Локальная память переносится между прогнозами одного испытательного процесса; в следующий независимый процесс она загружается из наследуемого генома. Обученная память закрытых испытаний не попадает в потомство.

Поиск получает пустую историю, наследуемую память и отдельный PRNG. Вывод разбивается на четверки `(target, position, kind, value)`. Target mod 6: modules/search/dialect/memory/router/architecture. Kind mod 3 для кода/памяти: replace/delete/insert. Для состава модулей kind mod 2 задаёт добавление/удаление; остаётся хотя бы один модуль, максимум восемь. Добавленный модуль содержит CONST. Кодирование новой инструкции: `op=value mod 19`, `arg=floor(value/19)-1724`. Следовательно, распределение доступных вставкой аргументов смещено; это ограничение синтеза, не произвольная программа из любой строки.

`position` одновременно выбирает модуль/семантический слот и индекс инструкции по модулю длины. Это заметное смещение поиска пилота. GP/random фиксируют поиск и перенаправляют target на программы; meta допускает программы/search; samo допускает все шесть целей. Неполная последняя четверка игнорируется. Меньше четырёх выходных слов означает бесплодие. Реальный список changes определяется сравнением до/после, а не названием попытки.

Fuel считает исполненные инструкции, включая вложенную семантику и router. Проверка формата, deepcopy, декодирование правок, JSON/SQLite и генерация задач — ограниченные доверенные накладные расходы, учтённые CPU/RSS процесса, но не приравненные к VM-шагам. Это ещё одна причина не объявлять общий VM ceiling доказательством равных полных вычислительных затрат разных условий.
