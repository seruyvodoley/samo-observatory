# Границы безопасности и оставшиеся угрозы

Дата оценки: 31 октября 2026. Первоначальные системные Python 3.9 и build-host Node 20 уже EOL: для будущего запуска выбраны поддерживаемые Python 3.12+ / Node 24 LTS. Python 3.12.13 подтверждён тестами и точным replay; Node 24 build требует отдельной проверки. Локальный пилот macOS. Приёмка общего Linux VPS **не выполнена**. TunnelDeck, EvidenceRAG и FlySwarm не изменялись; подключения к VPS не выполнялись.

## Исполняемая граница

`samo/vm.py:execute` принимает только ограниченные массивы пар целых чисел. Нет eval/exec, динамического импорта, shell, filesystem/network/process opcodes. Код, стек, память и вывод конечны, арифметика обрезается до 16 бит. Все CALL делят один Meter, вложенный CALL в семантике запрещён. Бесконечный цикл исчерпывает fuel; wall deadline проверяется каждые 32 шага. При типовой цене команды это дополнительный предохранитель, не внешняя гарантия завершения зависшего Python/runtime.

`samo/genome.py:validate` ограничивает геном 32 768 байт, 8 модулями, 4 семантическими программами, 96 инструкциями на программу и 64 словами памяти. Вход истории ограничен 256 значениями. Сеть/файлы/часы/секреты/тестовые seed не передаются VM. RAND разрешён только поиску и использует его отдельный PRNG. Этот интерпретатор — ограниченная capability-модель, **не доказательство полной изоляции**.

Испытатель, регистратор и VM находятся в одном доверенном Python-процессе. Это логическая независимость критерия от генома, а не процессная изоляция Python от собственных объектов. Уязвимость доверенного интерпретатора или модификация исходников администратором способны нарушить границу. Сильное разделение с IPC/отдельной VM остаётся будущей работой.

## Ресурсный контракт

Цель организма + потомков + runtime/генерации: CPU `40000/100000 us`, RAM `256000000`, swap 0, storage `1000000000`, pids 32. На macOS проверены только ограничения VM и фактические измерения RSS/CPU; средняя загрузка CPU не принудительно ограничена 40%. `watch` имеет кооперативное pacing, что не заменяет cgroup. Нельзя переносить этот режим на рабочий VPS как готовую защиту.

Доверенные evaluator/recorder в текущей реализации включены в тот же процесс и более строгий совокупный бюджет, а не вынесены в бесконечный вспомогательный ресурс. Экспортёр проектируется отдельно: 10% одного CPU, 128000000 RAM, pids 4, swap 0. Архив — 64000000 байт; SQLite rollback journal учитывается консервативно, но kernel FS quota ещё необходима. Экспортный volume — 16 MB; снимок ≤4 MB. Логи процесса по шаблону не пишутся в бесконечный journal; научные исходы в SQLite. Всё требует проверки на фактической системе.

## Приёмка перед производственным запуском

В одноразовой отдельной Linux VM с инертным canary вместо TunnelDeck: записать kernel/systemd/FS версии; проверить реальные cpu.max, memory.max, memory.swap.max, pids.max, read-only root/mount/PID/network namespaces, UID/capabilities/seccomp. Проверить бесконечный цикл и смерть supervisor; aggregate CPU/RAM всех процессов; RAM/swap/OOM; disk/inodes/tmp/deleted-open-file/stdout flood; запрет сети/DNS/Unix control sockets/ptrace/cgroupfs; невозможность чтения canary secret и изменения его файлов. До нагрузки зафиксировать canary latency SLO. При непройденной пробе не ослаблять ограничения и не запускать на общем VPS.

`.example` unit-файлы — материал ревью, не принятая конфигурация. Наличие marker-файла само по себе не доказывает приёмку. Нет автоматической установки, доступа к серверу или изменения firewall/VPN/DNS. Нужны внешний watchdog и fail-closed preflight для реального запуска; сейчас полноценного production launcher нет.
