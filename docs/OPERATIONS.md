# САМО: действующая эксплуатация

Публичный адрес: [samo-observatory.duckdns.org](https://samo-observatory.duckdns.org/). Сайт и организм размещены на VPS; Caddy направляет только отдельный hostname обсерватории на read-only origin 127.0.0.1:4180. DuckDNS предоставляет имя, но не хостинг. Старый Cloudflare Pages проект и пустой namespace Workers KV удалены 2026-11-02 после проверки прямой публикации с VPS.

## Службы и данные

- `srv-samo.mount`: существующий расширенный ext4 loop, `/srv/samo`.
- `samo-web.service`: origin `127.0.0.1:4180`; отдельный UID; 10% CPU, 96 000 000 байт RAM.
- `samo-webproxy.service`: Telegram proxy type WEB, Telemt 3.5.16; private listener `127.0.0.1:18080`, exposed only through a private route on the observatory HTTPS host. Service limit: 5% CPU, 64 000 000 bytes RAM, swap 0; no capabilities and no firewall control. Client address and key are deliberately excluded from repository documentation.
- `samo-organism-v6.service`: протокол `samo-ecology-v6-morphology`, нейтральный поиск формы, новый episode 0; 40% одного CPU, 512 000 000 байт RAM, swap 0, TasksMax 16, watchdog 120 секунд. После технической ошибки Restart=on-failure, 30 секунд паузы, максимум три запуска за час.
- `samo-recorder-export-v6.timer`: каждые 30 секунд запускает доверенный exporter; он читает согласованную SQLite-копию в памяти, проверяет checkpoint/event commitments и атомарно заменяет `/srv/samo/site/data/ecosystem.json`. Каталог `site/data` принадлежит `samo-export`. Ошибка оставляет предыдущий документ. Timer включён в автозагрузку и активен.
- Прежний `samo-organism.service` (v5), его экспортный timer, checkpoint и публичный снимок сохранены; прежние unit больше не запускаются.
- `samo-publish.timer`: отключён 2026-11-02 после миграции сайта с Cloudflare Pages на прямую публикацию с VPS. Не включать повторно без нового решения об архитектуре.
- `samo-aux.slice`: exporter and WEB proxy share 10% CPU and 160 000 000 bytes RAM; the proxy has its own 5% CPU and 64 000 000 byte child ceiling. The retired publisher timer remains disabled.
- `samo.slice`: общий предел 60% CPU и 768 000 000 байт RAM; CPUWeight/IOWeight=10 понижают приоритет САМО относительно обычных системных служб, не меняя TunnelDeck. Сумма верхних RAM-бюджетов организма, web и auxiliary составляет 768 000 000 байт.

Oneshot exporter штатно находится в inactive между успешными запусками; это не отказ службы. `samo-recorder-export-v6.timer` active/enabled; `samo-publish.timer` после удаления Pages остаётся disabled. После развёртывания два внешних HTTPS-запроса с интервалом 35 секунд получили актуальный v6 snapshot: шаг вырос с 3 до 32, `snapshot_id` изменился, оба ответа были `200` и `Cache-Control: no-cache`. Самостоятельная работа не означает монотонного прогресса организма.

Код `/srv/samo/releases/core-v6/code` принадлежит root и защищён от записи организмом. Данные, SQLite, checkpoints, резервные копии, версии кода и временные файлы находятся в `/srv/samo`. Проект использует ext4 loop-файловую систему на 974 434 304 байта; при последней проверке занято 106 995 712 байт (12%), inode занято 476 из 26 752. Предельный размер образа — 999 866 368 байт. Публикация Pages не активна; ни организм, ни экспортёр не получают Cloudflare credentials. Синтезированный байткод не имеет opcode файлов, сети, процессов или shell. Отключены core dumps; прикладные stdout/stderr отключены. Общие системные Python/библиотеки, systemd и его lifecycle-журнал остаются общими ресурсами хоста.

## Хранилище

Перед расширением остановлены web/mount, проверен ext4 и создана проверенная gzip-копия первоначального образа на компьютере оператора. Хеши всех 45 исходных файлов совпали после расширения. Сам образ не пересоздавался.

Финальный image `/var/lib/samo/volume.img`: **999 866 368 байт**, с резервом 133 632 байта общего 1-GB envelope под ограниченную root-owned unit-метаинформацию вне образа. Доступная ёмкость ext4 меньше из-за служебных структур; фактические значения приведены в `output/vps-final-status.json`. Общие systemd lifecycle messages отдельно принадлежат системному журналу хоста; его конфигурация не менялась.

Лимит inode — 26 752. Отдельная disposable Linux VM подтвердила inode ENOSPC и полный block ENOSPC для 1-GB image. В production намеренно диск не заполнялся. При заполнении filesystem на 80% показывается warning, на 90% runner приостанавливает новые попытки, не удаляя научные данные. Состояние наблюдений устаревает честно. Ограничение диска обеспечивает размер loop filesystem, а не `du`.

## История и воспроизведение

Каждый шаг — исполнение наследуемого поиска, свежая задача, реальная проверка и решение отбора. Перезапуск службы продолжает точный committed checkpoint: PRNG, активную популяцию и bounded diversity reservoir. Бесплодие/конкурентная гибель записываются отдельно. При полном вымирании появляются новые IDs и новый episode из зарегистрированного генератора либо случайного элемента разнообразия. Исторический лучший геном не восстанавливается.

SQLite удерживает последние 1024 полных попытки с положительными и отрицательными исходами. Прореживание старых raw trials явно считается и связывается SHA-256 цепочкой. До 64 описаний эпизодов остаются в checkpoint; более старые сворачиваются с явным счётчиком и обязательством. Полная реконструкция требует приватного seed, checkpoint и архивированной версии кода; на публичный сайт закрытые seeds не отправляются. Детерминизм VM задаётся fuel, а аварийный wall watchdog находится снаружи.

Для проверки использовать согласованную копию SQLite, не держать длительную read-транзакцию на рабочем файле:

```sh
PYTHONPATH=. python3 tools/replay_ecology.py PRIVATE_CONSISTENT_COPY.sqlite
```

На VPS archive quota 64 MB (с консервативным резервом rollback); raw retention ограничена протоколом. Никакого скрытого удаления неуспешных результатов, повышения точности по расписанию или заявления подтверждённых открытий нет. Постоянное поступление задач — не доказательство роста способностей.

## Обновление и остановка

Фронтенд: `npm run build --prefix web`, затем `python3 tools/deploy_vps.py`. Скрипт передаёт собранные статические файлы на VPS, сохраняя текущий публичный снимок `data/ecosystem.json`; публикация в Cloudflare больше не используется. Страница проверяет наличие нового снимка каждые 15 секунд; совпадающий ETag подтверждает отсутствие изменений без повторной загрузки большого JSON. После возврата во вкладку проверка запускается сразу. Экспорт на VPS остаётся отдельным циклом с периодом 30 секунд. Telegram WEB использует отдельный закрытый от документации путь на том же HTTPS-хосте; инструкция и ограничения — в [TELEGRAM-WEB-PROXY.md](TELEGRAM-WEB-PROXY.md).

Backend release сначала проходит отдельную VM. Архивировать исходники и протокол до обновления. При смене source hash продолжение запрещается по умолчанию. Для текущего исправления read-lock выполнена одноразовая явная recorder-only миграция `tools/migrate_recorder_snapshot.py`; её запись публична в `interventions`, а хеш активного checkpoint не изменялся. Не использовать эту миграцию для изменения отбора, VM ABI, задач или геномов; для этого нужен новый научный протокол/документированная миграция.

Остановка попыток: `systemctl stop samo-organism-v6.service`. Web и экспорт истории остаются независимы. Возобновление: `systemctl start samo-organism-v6.service`; после достижения StartLimit сначала устранить причину и явно выполнить `systemctl reset-failed samo-organism-v6.service`. Не подменять это созданием новой линии.

Удаление только САМО: сначала `disable --now` для `samo-organism-v6.service`, `samo-web.service`, `samo-recorder-export-v6.timer`, `samo-publish.timer`; проверить архивы, остановить mount и сохранить image. Удалять собственные unit-файлы, UID и image только после явного решения владельца о судьбе научного архива. TunnelDeck/firewall/существующий HTTPS не входят в процедуру. Старый Pages-проект и пустой связанный namespace KV удалены.

## Остаточные ограничения

Срок испытаний измеряется минутами, не годами. ARM Ubuntu VM и x86 VPS — разные архитектуры; лимиты cgroup повторно проверены на VPS, разрушительные probes выполнены только в VM. Общее ядро остаётся риском; абсолютная изоляция не доказана. Эксперимент не показал новой вычислительной способности; независимая точность не подтверждена. Реальный reboot VPS, физические мобильные устройства и полноценный screen-reader audit не выполнялись. `samo-observatory.pages.dev` не разрешается в DNS; он не отдаёт устаревшую страницу. Публичным остаётся HTTPS-адрес DuckDNS.
