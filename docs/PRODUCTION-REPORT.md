# Производственный результат САМО — 31 октября 2026

Публично работает [обсерватория](https://samo-observatory.duckdns.org/). Автономная популяция, научный SQLite-регистратор, независимые экспорт и публикация работают на VPS. Это новый протокол `samo-ecology-v2`; старый пилот остаётся отдельным архивом и не переинтерпретируется как успешное бесконечное развитие.

Этот отчёт фиксирует состояние на 31 октября 2026 года. 2 ноября сайт переехал с Cloudflare Pages на VPS; исторические разделы ниже описывают прежнее состояние публикации.

## Фактическое состояние

На контрольном срезе: **765 попыток**, 735 принятых потомков, 735 смертей форм, 4 активных формы, эпизод 1, повторных заселений 0. Это описательные счётчики, не доказательство полезного прогресса. Подтверждённых открытий нет. Автоматическая публикация после предыдущих 433 и 517 передала публичный снимок попытки 665; время и SHA-256 сохранены в status evidence.

Службы `samo-organism.service`, `samo-web.service`, `srv-samo.mount`, timers экспорта/публикации включены в автозагрузку. Oneshot export/publish завершаются с Result=success и штатно не работают между вызовами. Все фактические свойства сохранены в [vps-final-status.json](../output/vps-final-status.json). VPS не перезагружался; mount-cycle и восстановление процесса проверены.

## Проверки и обнаруженный инцидент

- Отдельная ARM Ubuntu 24.04 VM Lima/VZ, без host directory mounts; не общий VPS.
- **39 тестов** ядра/регистратора, включая crash-before-commit, tamper rejection, явное повторное заселение, свежие задачи и регистрацию прореживания.
- Проверены read-only code/`/etc`, недоступность `/root`, запрет AF_INET socket, неизвестных opcodes и неограниченных VM loops (fuel trap).
- Два дочерних CPU worker вместе использовали **3 243 981 000 ns за 8 секунд** при ceiling 40%. Отдельная попытка выделить 650 MB при 512 MB завершилась **oom-kill**. На production такие разрушительные probes не выполнялись.
- 1-GB image: создание файлов остановилось по inode после 26 741 файла; oversized allocation завершился **ENOSPC**, доступно 0. [Лог](../output/linux-storage.log).
- Производственный SIGKILL: checkpoint 247 → 252, новый PID, NRestarts=1, web HTTP 200 во время отказа. [Лог](../output/vps-crash-recovery.log).
- Длительное чтение старой реализации exporter могло блокировать writer. На попытке 433 runner остановился после ограниченного числа технических перезапусков. Исправлена изоляция снимка через SQLite online backup в память; явное инфраструктурное вмешательство хранит old/new source hash и **неизменённый state hash**. После исправления администратор сбросил StartLimit, продолжилась та же популяция/PRNG, без отката к лучшему организму. Инцидент не скрыт и не классифицируется как эволюционная гибель.
- Копия производственного архива: **433/433** событий и checkpoint точно воспроизведены в Linux VM. Дополнительный длинный VM-прогон: **1768** шагов, последние **1024** event hashes и hash root сокращённой истории точно воспроизведены. [Логи](../output/linux-vps-replay.log), [retention replay](../output/linux-retention-replay.log).
- Публичный браузер: **111 проверок**, ошибок 0, failed 0; все восемь разделов, вложенные URL/reload, Back/Forward, клавиатура, мобильные размеры, архивные и аварийные состояния. [QA](../output/playwright-public/qa.json).

## Публичная доставка и доступы

В аккаунте Cloudflare нет доменных зон, поэтому именованный Tunnel не использован. Разрешённый fallback Pages имеет постоянный `pages.dev` адрес. Pages Function делает только чтение одного заранее проверенного KV-документа, без управляющих команд и без исполнения генома. Publisher работает отдельным UID в общем auxiliary budget. JSON меняется примерно раз в три минуты без rebuild; возможна дополнительная KV/cache задержка. Бесплатные лимиты не повышались, платные планы не подключались. Приватные seeds/targets/PRNG и OAuth не публикуются.

OAuth renew проверен на VPS. Credential 0600 находится в 0700 каталоге publisher и не доступен организму. Grant сейчас имеет более широкие полномочия Wrangler, чем только KV; это остаточный риск для доверенного publisher, а не доступ генома. Секреты в чат не передавались. Локальная первоначальная сессия не является источником текущего refresh token; для администрирования deployment используется `tools/deploy_pages.py` через существующий SSH.

## TunnelDeck и эксплуатационные границы

Три проверенные службы TunnelDeck были active до и после; VPN/HTTPS/firewall/routing/config не изменялись. Общий VPS не перезагружался. Полный трафиковый тест всех VPN-функций не выполнялся и не объявляется доказанным.

Испытательный срок — около получаса в VM плюс рабочий период на VPS; это не доказательство многолетней надёжности. Общее ядро остаётся остаточным риском, даже с отдельными UID, cgroups и capability-free VM. Не подтверждены появление полезных способностей, специализации или собственного нового языка. Система продолжает реальные попытки, а не гарантированное улучшение. Требований к внешней авторизации для текущей публикации больше нет; возможный отзыв/истечение доступа виден как сбой доставки и возраст последнего наблюдения.
