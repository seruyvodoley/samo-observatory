## Конкретная причинная цепочка

1. `apply_edits` интерпретирует поле value одновременно как opcode и operand: `[value % 19, value // 19 - 1724]`. Поэтому value=0 однозначно создаёт CONST -1724. В 16-битной VM это число 63812. Детерминированный контроль воспроизводит декодирование.
2. Search VM получает пустую историю. HIST без истории возвращает 0; MEM может вернуть 0; пустой стек в конце исполнения тоже возвращает 0, но EMIT требует непустого стека. На свежем checkpoint все четыре search-программы реально выдают один квартет `[63812,35084,63812,0]`. Его target modulo 6 равен 2: вставка в собственный язык. Это не независимая равномерная мутация.
3. Повторение таких правок и рекомбинация распространяют CONST. Когда выбранный код достигает MAX_CODE=96, очередная вставка ничего не меняет. Поэтому жизнеспособность потомка, изменение генома и принятие — разные события. Система может регистрировать новый ID и замену популяции при прежнем хеше. Эти записи не являются открытием или новым поведением.
4. Избыток CONST -1724 не означает, что именно оно выдаётся как прогноз. У свежих форм router возвращает 63812; modulo 8 выбирает модуль с индексом 4, то есть №5. Его единственная команда — CONST 0. На проверенном входе все четыре формы возвращают 0, без ошибки VM, затрачивая 27 инструкций. Текущий фенотип вырожден в постоянный нулевой ответ.
5. Exact-match почти всегда равен нулю у такого предсказателя. Все формы ведут себя одинаково; ребёнок и случайный incumbent получают одну оценку на одной задаче. Delta равна нулю; `exp(min(0,delta/0.08))=1`. Даже редкие совпадения с нулём не создают различия между ними.
6. Турнир выбирает родителя по одной текущей семье; замена сравнивает ребёнка со случайным участником. Нет проверки удержания прежних семейств, элитизма или архива защищённых способностей. Поэтому ранняя способность предсказывать постоянные ряды может быть утрачена через нейтральный дрейф и последующую замену. Полный исторический путь каждого исчезнувшего успеха нельзя восстановить по прореженному окну; это ограничение доказательства, а не повод домыслить предков.

Prequential commit до раскрытия следующего числа предотвращает прямой доступ к ответу, но не превращает использованный для отбора результат в независимое подтверждение способности. До исправления подписи «проверочный отрезок» допускали такое прочтение. На опубликованной странице испытаний теперь явно указаны обучающий источник, отсутствие независимой подтверждённой оценки в этом потоке и недостаточность данных. Добавлено конкретное объяснение решаемой задачи.

## Контроль представимости

Отдельные контрольные геномы, не добавленные в эволюцию:

- HIST: exact=1 на постоянных рядах.
- `HIST HIST HIST(1) SUB ADD`: exact=1 на арифметических рядах.
- HIST(p−1): exact=1 для каждого фиксированного периода p=2…5.

Это доказывает представимость и корректность исполнения этих решений, а не способность автономного поиска их открыть. Для каждого контроля и текущих форм сохранены exact-match, нормированная абсолютная ошибка, побитовая точность, отказы и fuel по шести семействам. Побитовая точность не равна полезности прогноза; отказ получает ошибку 1 и битовую оценку 0. Текущие данные не подтверждают поиск универсального периодического или арифметического решения за проверенный бюджет.

Отложенный набор теперь раскрыт диагностике и не является закрытым подтверждающим тестом. n=5 мало; нет основания объявлять общую эффективность, преимущество по всем семействам, статистически подтверждённое превосходство или многолетнюю устойчивость. Нужен следующий заранее зарегистрированный подтверждающий опыт с новым закрытым набором и выровненной фактической стоимостью. Production v2 оставлен работающим: неподтверждённый v3 не подменяет научную историю.

## Воспроизведение

Из корня проекта: `PYTHONPATH=. python3 tools/zero_accuracy_chain.py`, затем `PYTHONPATH=. python3 tools/zero_accuracy_diagnostics.py` и `PYTHONPATH=. python3 tools/zero_accuracy_cpu_matched.py`. Последние две команды перезаписывают локальные диагностические результаты; исходные production-снимки не меняются. CPU-ограниченный опыт зависит от скорости машины, фактические шаги и расходы регистрируются. Seed, исходные и конечные геномы, события, показатели и расходы доступны в `output/zero-audit/`. Код сравнения меняет только локально загруженную копию функции advance; рабочие scientific-модули и production-протокол не изменены.
