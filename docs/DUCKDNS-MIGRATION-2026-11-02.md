# Переезд обсерватории на VPS — 2026-11-02

## Что изменено

- Создан бесплатный адрес `samo-observatory.duckdns.org`, он указывает на VPS. DuckDNS обновляет DNS-запись; сайт обслуживает VPS.
- Текущая сборка React размещена в `/srv/samo/site`. Живой файл `data/ecosystem.json` не заменялся сборкой сайта и продолжает обновляться локальным экспортёром.
- В Caddy добавлен отдельный hostname для обсерватории с HTTPS и проксированием на прежний loopback origin `127.0.0.1:4180`. Настройки TunnelDeck, firewall и прежние HTTPS-маршруты не менялись.
- Проверены публичные `/`, `/memory`, `/evolution` и новые JS-ресурсы. Все открылись с HTTPS; корневая страница показала текущий шаг эксперимента. Прежний сайт `osnovanie.duckdns.org` продолжил отдавать HTTP 200.
- Cloudflare Pages проект `samo-observatory` удалён из панели аккаунта. `samo-observatory.pages.dev` больше не является адресом сайта. Workers KV publisher timer отключён; recorder/exporter и эволюционный процесс не затронуты.
- KV namespace и его содержимое намеренно не удалялись: запрос касался сайта, а не удаления научных снимков.
- Для владельца на HTTPS-хосте настроен отдельный закрытый в документации маршрут Telegram WEB к loopback-only Telemt listener. Обычный посетитель получает обсерваторию; точные адрес и ключ не включены в репозиторий.
- Telemt работает как отдельная служба с лимитами 5% CPU, 64 МБ RAM, без swap и без Linux capabilities. Бинарный файл, конфигурация и runtime state физически хранятся на loop-томе; исполняемый файл открывается отдельным read-only bind mount из-за `noexec` на основном томе.

## Текущее состояние VPS

На момент переезда `samo-web.service`, `samo-organism.service`, `samo-recorder-export.timer`, `samo-webproxy.service` и TunnelDeck HTTPS service были активны. `samo-publish.timer` переведён в disabled/inactive. Отдельная резервная копия старого содержимого сайта сохранена в `/srv/samo/backups/site-before-duckdns-20261102`.

## Обновление сайта

Собрать сайт командой `npm run build --prefix web`, затем выполнить `python3 tools/deploy_vps.py`. Deploy-скрипт исключает живой `data/ecosystem.json`, так что сборка фронтенда не затирает актуальную телеметрию.

## Ограничения

В текущем окне браузерной проверки страницы «Жизнь», «Память» и «История» отрисовались без ошибок маршрутизации. Telegram WEB path прошёл HTTPS и backend health checks; отдельное подключение из Telegram-клиента владельца не выполнялось. Полный набор мобильных физических устройств повторно не тестировался при миграции. Доступность зависит от самого VPS, его сетевого маршрута и DNS; внешнего CDN перед сайтом больше нет.
